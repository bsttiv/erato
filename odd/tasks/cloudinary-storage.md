# Cloudinary storage

Objective: replace Cloudflare R2 with Cloudinary for demo audio.
Branch: feat/cloudinary-storage, fast-forwarded into main. Delivery strategy: ask-on-risk. Test runner: `make test`.

## Specs

- S1: "quiero cambiar cloudflare r2 por cloudinary, que era lo original que estaba usando"
- S2: `songs.demos[]` drops `r2_key` and adds `cloudinary_public_id` (string) and `format` (string). No new indexes.
- S3: Browser uploads go directly to Cloudinary through a signed multipart POST with `resource_type: video` and `type: authenticated`.
- S4: Confirmation reads format, size and duration from Cloudinary and enforces the existing limits and the 2 GB quota. `ffprobe` and the copy from `uploads/` to `songs/` are removed.
- S5: Playback uses `private_download_url` with a 15-minute expiry (option A).
- S6: Deletion uses `uploader.destroy` before MongoDB changes.
- S7: `boto3` leaves and `cloudinary` enters; configuration is `CLOUDINARY_URL`, documented in `.env.example`.
- S8: SeaweedFS leaves. Tests use a Cloudinary fake. Without credentials the app starts and demos report a clear error.
- S9: Docs, legal text and the migration plan reflect Cloudinary.
